# Proposal: data-external-database-sources

## Why

Three rows of the buildiq matrix ask for one thing from three sides: an app a
maker builds reads and writes the tables of a database the organisation already
runs. No tender, featureRequest or roadmap row carries them (`demand` is empty
in gap-rows.json); the competitor cells are the demand, and two of the rows sit
in buildiq's core area (data, apps).

buildiq matrix, row `data-external-db`, "Read and write records in an external
SQL database such as PostgreSQL or MySQL.", rated `no`. Five competitors rated
`yes`:

- NocoBase: "packages/plugins/@nocobase/plugin-collection-fdw/src/client/index.tsx:147
  "Connect to foreign data" collection template for remote MySQL and PostgreSQL
  tables (package.json:10), registered at line 257, optional preset plugin
  packages/presets/nocobase/package.json:36; full external data sources are
  Standard edition, commercial" (https://www.nocobase.com/en/commercial).
- Budibase: "packages/server/src/integrations/index.ts:29 DEFINITIONS register
  postgres.ts, mysql.ts, microsoftSqlServer.ts, oracle.ts, mongodb.ts,
  snowflake.ts and more; packages/builder/src/pages/builder/workspace/[workspaceId]/data/new.svelte:95-105
  lists them to connect, then tables are read and written through the grid".
- Appsmith: "app/server/appsmith-plugins/postgresPlugin/src/main/java/com/external/plugins/PostgresPlugin.java:164
  executor runs read and write SQL, siblings mysqlPlugin, mssqlPlugin,
  oraclePlugin, redshiftPlugin, snowflakePlugin".
- Mendix: "external database connection to Microsoft SQL, MySQL, Oracle,
  PostgreSQL or Snowflake" (https://docs.mendix.com/refguide/external-database-connection/).
- Microsoft Power Apps: "virtual tables contain data sourced from an external
  database such as Azure SQL Database; connectors for SQL Server"
  (https://learn.microsoft.com/en-us/power-apps/maker/data-platform/create-edit-virtual-entities).

buildiq matrix, row `int-sql-query`, "Write a SQL query against a connected
database and show the result.", rated `no`. Four competitors rated `yes`:

- NocoBase: "packages/plugins/@nocobase/plugin-collection-sql/src/client-v2/plugin.tsx:27
  "SQL collection" template whose query result is shown by any block".
- Budibase: "packages/builder/src/components/integration/QueryViewer.svelte:361-362
  SQL editor for SQL datasources with paginated read (:109-110) and a results

- Appsmith: "MySqlPlugin.java:164 and postgresPlugin/.../PostgresPlugin.java:164
  execute builder SQL with prepared statements; results render in the query

- Mendix: "Query field: write an SQL query to retrieve data and run it"
  (https://docs.mendix.com/refguide/external-database-connection/).

buildiq matrix, row `app-create-from-database`, "Generate an app from the tables
of an existing database.", rated `no`. Two competitors rated `yes`:

- Budibase: "DatasourceModal.svelte:89 'Autogenerated screens' multi-selects
  tables and views of any datasource (line 101-121); CreateScreenModal.svelte:131
  createScreens loops the templates".
- Microsoft Power Apps: "you can create a Start with data app for your SQL
  Server data, New app > Start with data > Connect external data, to get a basic
  working app"
  (https://learn.microsoft.com/en-us/power-apps/maker/canvas-apps/connections/sql-connection-overview).

What buildiq does today, per the matrix `built.evidence`:

- `data-external-db`: "no external SQL data-source hits ... The only alternative
  data-source origin is 'OpenConnector'
  (src/components/page-editor/DataSourceOriginToggle.vue:13-30), which is a
  generic API-endpoint picker (ConnectorSourcePicker.vue), not a direct
  SQL/PostgreSQL/MySQL connection".
- `int-sql-query`: "no connected-database query feature; data sources are
  OpenRegister registers or integriq endpoints only
  (DataSourceOriginToggle.vue:13-42)".
- `app-create-from-database`: "No controller or service resolves an external
  database connection to auto-generate a schema/app."

What that evidence leaves out: the data plane already exists in OpenRegister.
Its `dbal-virtual-registers` spec (status done, changes archived 2026-07-09)
turns a MySQL, PostgreSQL or SQLite database into a register whose tables are
schemas, served live, with writes when the source allows them. The source screen
offers it (`openregister/src/modals/source/EditSource.vue:229`, "Database
(virtual register)"), and `introspect` is routed
(`openregister/appinfo/routes.php:227`). Buildiq's page editor lists every
register OpenRegister returns (`src/composables/useRegisterPicker.js:124`), so a
maker can bind a page to such a register once an administrator has made it.
That is read from code, not driven. Nothing in buildiq knows the register is a
database, whether it takes writes, how to build an app from its tables, or how
to ask it a question in SQL. This change builds that half.

## What changes

- The app settings list the databases connected in OpenRegister and bind one to
  the app with a picker, next to today's slug field for data registers.
- The page editor marks a table that lives in a connected database. When the
  database does not take writes, the index and detail editors switch off the
  add, edit and delete actions and say why.
- The create-app wizard gains "Start from a database": pick a connected
  database, tick tables, review the pages, create. Each table gets an index
  page, a detail page and a menu entry, and the database stays bound as a data
  register.
- Generated pages keep the database register and table slugs; the per-version
  rewrite that namespaces the app's own schemas leaves them alone.
- Administrators get a query editor: write one read-only SQL query against a
  connected database, preview up to 50 rows, and save it as a query table that
  pages bind to like any other table. OpenRegister runs the query.

## Rows this closes

| matrix | row id | row name | own rating | what is missing |
|-|-|-|-|-|
| buildiq | data-external-db | Read and write records in an external SQL database such as PostgreSQL or MySQL. | no | a way to bind a connected database from the builder, and pages that follow its write setting |
| buildiq | int-sql-query | Write a SQL query against a connected database and show the result. | no | a query editor with a result preview, saved as a table pages can use |
| buildiq | app-create-from-database | Generate an app from the tables of an existing database. | no | a wizard path that builds pages and menu entries from a connected database's tables |

## Existing work it builds on

- `data-registers-schema-declaration` and `data-registers-runtime` (open, every
  task ticked): `Application.dataRegisters`
  (`lib/Settings/register.d/20-data-registers.json:7`), the picker that hoists
  bound registers (`src/composables/useRegisterPicker.js:122-200`) and the
  settings rows (`src/modals/AppSettingsModal.vue:58-95`). A connected database
  is bound through this same property.
- `openspec/specs/openconnector-api-sources` (REQ-OCAS-001): the OpenConnector
  origin in `DataSourceOriginToggle.vue`. A database stays on the OpenRegister
  origin (design D1).
- `openspec/specs/application-creation-wizard`: the four-step wizard and its
  atomic creation with rollback, which "Start from a database" extends.
- `openspec/specs/data-import-wizard`: copies a file's rows into a schema. This
  change reads rows in place and copies nothing.
- openregister `dbal-virtual-registers` (spec, done): the connection,
  introspection, live reads and opt-in writes this change consumes.

## Sibling halves

- openregister owes the query table. A `dbal-source` schema whose config names a
  `query` instead of a `table`, checked as one read-only `SELECT` or `WITH`
  statement, run in a read-only transaction with a statement timeout and the
  provider's row cap, values bound as parameters. It also owes a preview route,
  `POST /api/sources/{id}/query-preview`, gated like `introspect` (administrator
  and organisation-scoped, `lib/Controller/SourcesController.php:602-605`), that
  returns at most 50 rows and the columns it found. No open openregister change
  covers it: a search of `openspec/changes/*/proposal.md` at development
  `ae898b0` for saved, raw or maker SQL queries found none.
- nextcloud-vue: none. `CnDataTable` and the `showAdd`, `showEditAction` and
  `showDeleteAction` props of `CnIndexPage` exist at 2.57.1.

## Out of scope

- Creating the database source and its credential. OpenRegister's source screen
  does that, and the password stays in the credential store (ADR-064).
- Writing through a query table. A query table is read only.
- Database engines OpenRegister's provider does not drive (it drives
  `pdo_mysql`, `pdo_pgsql` and `pdo_sqlite`).
- Copying or syncing external rows into OpenRegister.
