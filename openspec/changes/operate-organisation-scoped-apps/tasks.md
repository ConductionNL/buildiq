Record the answer and, if hidden, the openregister change that makes `all` apps visible (sibling half).
  > Checked 25 Nov 2026 on Nextcloud 34.0.6 (MariaDB) with OpenRegister main 55f2aa3e, multitenancy on (`adminOverride` true). Setup: organisations Org A (admin, alice) and Org B (bob). An app `org-a-app` was created by the wizard with Org A active, so `@self.organisation` is Org A and `organisationScope` is absent (= `all`). It was published, with alice and bob both viewers.
  > **Answer: hidden.** alice gets it in `GET /api/applications` and its manifest (200). bob gets an empty list, 404 on the manifest, and 404 on the OpenRegister object itself: OpenRegister's organisation filter hides the Application before buildiq sees it. OpenRegister's `publishedObjectsBypassMultiTenancy` setting is no way out: no code reads it.
  > **What makes `all` apps visible (sibling half):** OpenRegister's `rbac-cross-organisation-is-explicit` is built on main; its open task 5.1 is one marker PR per app. Tried live on `built-app`: read rules `["authenticated", {"group": "authenticated", "match": {"organisationScope": "all"}, "crossOrganisation": true}, {"group": "authenticated", "match": {"organisationScope": {"$exists": false}}, "crossOrganisation": true}]`. Two rules are needed because an absent scope means `all` and `$ne` drops NULLs. With them, bob's app list shows the `all` app and does not show it once it is set to `holder`.
  > **Still hidden after that:** the manifest. The production `applicationVersion` (and the version's data register) are held by Org A too, so `ManifestResolverService` finds the Application but not its version ("Application has no manifest"). Opening an `all` app across organisations therefore needs a cross-organisation read of its versions as well. That is an access-control choice (mark `applicationVersion` reads `crossOrganisation`, or read the version of an Application the caller may see with the organisation filter off), and it is left to Ruben (queued). No code is changed for it here. T04 is not affected: it guards the same entry points either way.
